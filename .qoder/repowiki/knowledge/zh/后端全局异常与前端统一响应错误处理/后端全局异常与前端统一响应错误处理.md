## 1. 整体方案

本仓库采用 **Spring Boot + DDD** 的后端架构，配合 Vue3 + Axios 的前端单页应用。错误处理分为三层：
- **领域层（domain）**：通过抛出 `IllegalArgumentException` / `IllegalStateException` 表达参数非法与业务规则违反。
- **接口层（interfaces）**：通过 `@RestControllerAdvice` 的 `GlobalExceptionHandler` 将异常统一收敛为 `R<T>` 返回体；认证失败由 `JwtAuthInterceptor` 直接写 401。
- **前端（frontend）**：Axios 响应拦截器根据 `res.code` 统一提示并处理 401 跳转登录。

没有自定义业务异常类、没有统一的错误码枚举，也没有 `try/catch` 在 Service 中吞异常——所有业务异常都靠“抛标准异常 + 全局处理器”这一条路径完成。

## 2. 关键文件

| 文件 | 作用 |
|---|---|
| `wzoto-backend/wzoto-interfaces/src/main/java/com/wzoto/interfaces/common/GlobalExceptionHandler.java` | 全局异常处理器，捕获 `IllegalArgumentException`、`IllegalStateException`、`MethodArgumentNotValidException`、`BindException`、`RuntimeException`、`Exception` |
| `wzoto-backend/wzoto-interfaces/src/main/java/com/wzoto/interfaces/common/R.java` | 统一返回体 `{code, msg, data}`，提供 `ok()` / `fail()` / `unauthorized()` / `badRequest()` 工厂方法 |
| `wzoto-backend/wzoto-infrastructure/src/main/java/com/wzoto/infrastructure/interceptor/JwtAuthInterceptor.java` | JWT 认证拦截器，未携带或无效 Token 时直接 `response.setStatus(401)` |
| `wzoto-frontend/src/utils/request.js` | Axios 实例，请求头自动注入 Bearer Token，响应拦截器统一处理 `code !== 200`、401 跳转、网络错误 |
| `wzoto-frontend/src/utils/toast.js` | 基于 Element Plus `ElMessage` 的轻量 toast 封装 |
| 领域实体（如 `Booking.java`、`Child.java`、`LearningTask.java` 等） | 在 setter / 业务方法中 `throw new IllegalArgumentException(...)` / `throw new IllegalStateException(...)` 表达校验与状态约束 |

## 3. 架构与约定

### 后端异常分类与映射
`GlobalExceptionHandler` 按异常类型区分 HTTP 语义：
- `IllegalArgumentException` → 400，消息透传（用于参数非法）
- `IllegalStateException` → 400，消息透传（用于业务状态不合法）
- `MethodArgumentNotValidException` / `BindException` → 400，拼接字段校验错误列表
- `RuntimeException` → 500，记录堆栈日志
- 兜底 `Exception` → 500，固定消息“系统异常，请稍后重试”

### 领域层错误表达
领域实体内部做自校验与状态守卫，例如：
- `Booking` 中检查“无权操作此预约”、“当前状态不允许确认/拒绝/取消”、“只有已确认的预约才能标记完成”等，分别抛出 `IllegalArgumentException` 或 `IllegalStateException`。
- `Child`、`LearningPlanConfig`、`CourseWatchRecord` 等对空值、范围、取值合法性抛出 `IllegalArgumentException`。
- `LearningTask`、`FeatureOrder`、`ChildAchievement` 对重复操作、非法状态迁移抛出 `IllegalStateException`。

这些异常被上层 ApplicationService 透出，最终由 `GlobalExceptionHandler` 转为 `R.fail(...)`。

### 认证错误
认证不在 `GlobalExceptionHandler` 中处理：`JwtAuthInterceptor.preHandle` 在未携带有效 Token 或解析失败时直接 `response.setStatus(401)` 并返回 false，不走 Controller 流程。前端 `request.js` 在响应拦截器中对 `status === 401` 执行 `userStore.logout()` 并跳转到 `/login`。

### 前端错误呈现
- 成功：`res.code === 200` 直接返回数据。
- 业务失败：`res.code !== 200` 调用 `showToast(res.msg || '请求失败')`，然后 `Promise.reject(new Error(...))`，由页面 try/catch 决定是否继续。
- 401：清除用户态并跳转 `/login`。
- 网络错误：根据是否有 `error.response` 显示“网络错误(status)”或“网络连接失败，请检查网络”。

## 4. 约定与约束

- **领域层禁止吞异常**：所有参数与状态校验通过 `throw new IllegalArgumentException/IllegalStateException` 表达，不在方法内 catch 后返回 null。
- **Controller 层不自行 try/catch**：业务异常一律上抛，由 `GlobalExceptionHandler` 统一转成 `R` 返回体。
- **统一返回体**：所有接口响应必须走 `R.ok(data)` / `R.fail(msg)` / `R.badRequest(msg)` / `R.unauthorized(msg)`，禁止直接返回裸对象。
- **认证失败不走 R**：JWT 拦截器直接写 401，前端据此触发登出重定向。
- **前端统一错误入口**：所有 HTTP 调用必须使用 `src/utils/request.js` 导出的 axios 实例，禁止绕过响应拦截器。
- **用户可见错误**：仅通过 `toast.js` 的 `showToast` 展示，避免直接使用 `alert` 或 Element Plus Message 散点调用。

该方案简洁但较原始：没有统一的业务异常基类、没有错误码枚举、没有跨模块的错误传播约定，错误信息以字符串形式在异常消息中传递。
